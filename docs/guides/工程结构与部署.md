# AMMR 工程结构、统一启动与部署

## 1. 工程边界

```text
/home/ai/project/yj/
├── ammr_teleop/                 # 统一XR控制与真机部署源
│   ├── src/ammr_teleop/common/ # 双模式公共契约、IK、映射、轨迹
│   ├── src/ammr_teleop/sim/    # 仿真ROS控制适配（部署时排除）
│   ├── src/ammr_teleop/real/   # 真机、AGX Recorder/回放、控制中心
│   ├── models/kinematics/      # 真机与仿真共用的无网格IK URDF
│   └── ros2_ws/src/lifting_msg_pkg/
└── ammr_sim/                    # 独立Isaac环境与全部仿真资产
    ├── assets/
    ├── src/ammr_isaac/
    └── src/ammr_sim/           # 相机共享内存和仿真Recorder
```

依赖方向为 `ammr_sim -> ammr_teleop.common`。真机模式不会导入
`ammr_teleop.sim`；部署 manifest 也会物理排除它。

## 2. 仿真启动

终端一只启动 Isaac，默认创建和预热三路相机：

```bash
cd /home/ai/project/yj/ammr_sim
export ROS_DOMAIN_ID=0
./scripts/ammr_sim.sh simulator
```

统一入口已内置遥操优化默认值，无需每次重复填写：

- 完整 `market001` 场景；
- 物理频率 60 Hz，渲染、相机和状态发布频率 30 Hz；
- 已验证无抖动的 `state` 关节执行模式；
- 启动时创建并预热头部、左腕和右腕三路相机；
- 默认在 `56555/56556/56557` 三个独立 ZMQ 端口发布头部、左腕和右腕图像；
- 预先准备 Recorder，遥操端是否允许录制仍由 `--record` 控制。

命令行中显式给出的参数会覆盖默认值。需要使用轻量遥操场景时使用：

```bash
./scripts/ammr_sim.sh simulator --scene teleop-lite
```

只排查控制链路、不需要 ZMQ 图像流时，可以使用：

```bash
./scripts/ammr_sim.sh simulator \
  --no-publish-zmq-camera-streams
```

终端二从统一遥操作工程连接仿真：

```bash
cd /home/ai/project/yj/ammr_teleop
export ROS_DOMAIN_ID=0
./scripts/ammr.sh teleop --sim \
  --profile piper_absolute_smooth_v1
```

允许左 X 录制 episode：

```bash
./scripts/ammr.sh teleop --sim --record \
  --profile piper_absolute_smooth_v1
```

`--sim` 只选择控制目标，不负责启动/关闭 Isaac。

### 2.1 仿真与真机统一控制接口

Isaac 对外直接模拟现有真机接口：左右臂分别使用
`/left/control/joint_states`、`/right/control/joint_states`，反馈分别使用
`/left/feedback/joint_states`、`/right/feedback/joint_states`；底盘使用
`/cmd_vel`，升降柱使用 `/LiftingMotorService`。左右臂控制门和急停服务也与
真机同名。仿真不再公开 `/ammr/joint_command` 和 `/ammr/joint_states` 这组
21 维接口。

14 维契约只用于 VLA、录制和回放的数据组合：左臂 6 + 左夹爪 1 + 右臂 6 +
右夹爪 1。发布前拆成左右各 7 维，反馈后再合成 14 维。底盘与升降柱始终是
独立控制通道；Isaac 仅在进程内部将这些通道组装成 21 维执行向量。

三路 Isaac 相机在启动时静态创建和预热，并通过有界共享内存提供给
Recorder。统一启动入口默认启动独立 ZMQ relay，在 `56555/56556/56557`
发布三路 JPEG；三路消息携带相同的 `bundle_sequence` 和仿真时间戳。
ZMQ relay 只读取最新完整共享帧，不阻塞物理、渲染或 Recorder。仿真录制仍直接
读取共享内存原始 RGB，不经过 JPEG 和网络。

### 2.2 底盘与升降柱速度

速度参数属于统一遥操端，应写在 `ammr.sh teleop --sim` 后，不是写在
Isaac 启动命令后。当前默认上限为：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--max-linear-x` | `0.20` | 底盘前后速度，m/s |
| `--max-linear-y` | `0.15` | 底盘横移速度，m/s |
| `--max-angular-z` | `0.30` | 底盘旋转速度，rad/s |
| `--lift-speed` | `40` | 升降柱最大速度，mm/s |
| `--lift-command-period` | `0.20` | 升降速度指令最长重发周期，s |

仿真调试可先使用下列中等提速值：

```bash
./scripts/ammr.sh teleop --sim \
  --profile piper_absolute_smooth_v1 \
  --max-linear-x 0.40 \
  --max-linear-y 0.30 \
  --max-angular-z 0.60 \
  --lift-speed 60
```

这些参数只覆盖当次遥操进程，不会修改 profile，也不会改变 ROS
Topic/服务契约。真机上不应直接照搬仿真提速值，仍需按硬件安全上限验收。

Isaac 现在会在每个 PhysX 子步内单独更新 3 个底盘关节和 2 个升降关节，
不再等到渲染循环才一次性积分。目标速度还会在 Isaac 内按物理 `dt` 做线性
加减速：持续推动摇杆时速度线性增加，松开时线性降为零。该回调不会改动
机械臂的 `state` 执行链路。

加速度参数属于 Isaac 启动端，已内置以下默认值：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--base-linear-acceleration` | `0.4` | 底盘 X/Y 加减速上限，m/s² |
| `--base-angular-acceleration` | `0.6` | 底盘旋转加减速上限，rad/s² |
| `--lift-acceleration` | `0.08` | 升降柱加减速上限，m/s² |

例如要让启停更柔和，可以在启动 Isaac 时降低加速度：

```bash
./scripts/ammr_sim.sh simulator \
  --base-linear-acceleration 0.25 \
  --base-angular-acceleration 0.40 \
  --lift-acceleration 0.05
```

`--lift-command-period` 只是遥操端对真机同名服务的指令重发周期；Isaac 会保持
最后一个有效速度，因此不需要通过缩短该周期来获得连续运动。

## 3. 真机启动

不带 `--sim` 默认为真机；现场建议显式写 `--real`：

```bash
cd /home/ai/project/yj/ammr_teleop
export ROS_DOMAIN_ID=101
./scripts/ammr.sh teleop --real --record \
  --profile piper_absolute_smooth_v1 \
  --enable-hardware-output \
  --hardware-components left_arm right_arm \
  --task "pick fruit"
```

`--hardware-components` 表示实际在线并持续发布命令的硬件，不再用它选择遥操侧。
左右臂默认都跟随 XR。仅操控左臂时仍保留双臂硬件并关闭右侧遥操：

```bash
./scripts/ammr.sh teleop --real --record \
  --profile piper_absolute_smooth_v1 \
  --enable-hardware-output \
  --hardware-components left_arm right_arm \
  --left-enable --no-right-enable \
  --task "left-arm pick"
```

仅操控右臂改为 `--no-left-enable --right-enable`。未操控侧会以平滑参数回到并
保持零位，但两侧 feedback/action 仍同步发布和录制。开始录制前应先按 Right B
使能，并等待未操控侧到达零位。仿真使用完全相同的 enable 参数。

使用 `./scripts/ammr.sh control-center` 时，可直接在网页 XR teleoperation 卡片
勾选 `Left enable`、`Right enable`。启动 Server XR 后选项锁定，停止后才能切换；
网页始终以双臂 hardware components 启动，只改变遥操选择侧。

真机 `--record` 只授权 XR 左 X 调用 AGX Recorder 服务；AGX Recorder 节点
仍需先在 AGX 启动。不带 `--record` 时遥操作保持可用，但左 X 不会录制。

在 AGX 本机另开终端启动 Recorder，并确保 `ROS_DOMAIN_ID` 与服务器端一致：

```bash
cd ~/yanjun/ammr_teleop

export ROS_DOMAIN_ID=101
export AMMR_RECORDER_PYTHON=/usr/bin/python3

./scripts/ammr.sh recorder \
  --domain-id 101 \
  --recording-frequency 30 \
  --data-dir ~/yanjun/ammr_teleop/datasets/ammr_real_xr \
  --task "pick fruit"
```

其中工程和数据目录也可由 `configs/paths.yaml` 的相对 AGX 路径统一提供。Recorder
启动成功后应提供 `/ammr/recording/set_enabled` 服务，随后服务器端的左 X
或键盘 `s` 才能开始、停止并保存 episode。

## 4. 数据集检查

录制完成后，在服务器对整个 LeRobot 数据集运行统一 Dashboard：

```bash
cd /home/ai/project/yj/ammr_teleop
./scripts/ammr.sh inspect-dataset \
  --dataset-path /home/ai/project/zw/openpi/dataset/ammr_pick_place
```

默认地址为 `http://127.0.0.1:8050`。它集中显示多条 episode 的实际采集率、
质量结果、关节跳变热力图，以及当前所选 episode 的 14 路 state/action 曲线。
只做批量契约校验时使用：

```bash
./scripts/ammr.sh inspect-dataset \
  --dataset-path /path/to/dataset \
  --validate-all --no-web
```

完整参数和指标定义见[数据集可视化与批量校验](数据集可视化与批量校验.md)。

## 5. 回放

```bash
# 仿真回放
./scripts/ammr.sh replay --sim --domain-id 0 --data-path /path/to/episode.parquet

# 真机回放（先做 validate-only）
./scripts/ammr.sh replay --real \
  --data-path /path/to/episode.parquet \
  --validate-only
```

仿真回放不会自动启动 Isaac。需要先在 `ammr_sim` 中运行
`./scripts/ammr_sim.sh simulator`，并保证两个进程的 `ROS_DOMAIN_ID`
一致。`--sim` 使 14 维回放器连接 Isaac 虚拟硬件接口；正常日志为
`AMMR replay target: ISAAC SIMULATION`，不会连接 Piper CAN 驱动。

### 5.1 真机回放 Topic 下发

真机回放前必须退出 XR 遥操作，避免两个进程同时发布双臂指令，并确认左右臂
驱动、反馈 Topic 和控制门服务已经启动。建议先完成上面的 `--validate-only`，
再执行一次不带 `--enable-hardware-output` 的 DRY-RUN。

回放默认为 `--no-smoothing`：从当前姿态到第一帧仍保留安全平滑进入，
episode 主回放段则直接下发按时间戳插值的 action，不再经过
velocity/acceleration/jerk 整形。反馈超时、控制门、关节限位校验和急停
仍然生效。命令频率默认为 `100 Hz`，`--speed 1.0` 按 episode 时间戳原速回放。

如需恢复 `piper_absolute_smooth_v1` 的速度/加速度/jerk 整形，显式加上：

```bash
./scripts/ammr.sh replay --sim --domain-id 0 \
  --data-path /path/to/episode.parquet \
  --smoothing \
  --profile piper_absolute_smooth_v1
```

```bash
# 在保存了 episode 的 AGX（或已同步数据的服务器）上执行
cd /path/to/ammr_teleop
export ROS_DOMAIN_ID=101

./scripts/ammr.sh replay --real \
  --data-path ~/yanjun/ammr_teleop/datasets/ammr_real_xr/data/chunk-000/episode_000000.parquet \
  --enable-hardware-output \
  --hardware-components left_arm right_arm
```

首次真机验收时可临时限制为低速短片段；这些参数会覆盖 profile 默认值，不是
常规回放必填项：

```bash
./scripts/ammr.sh replay --real \
  --data-path ~/yanjun/ammr_teleop/datasets/ammr_real_xr/data/chunk-000/episode_000000.parquet \
  --enable-hardware-output \
  --hardware-components left_arm right_arm \
  --speed 0.5 \
  --start-index 0 \
  --end-index 100 \
  --arm-velocity 0.20 \
  --arm-acceleration 0.80 \
  --arm-jerk 4.0
```

交互终端会在正式下发前等待 Space 确认；无人值守运行必须额外显式添加
`--start-immediately --no-keyboard`。回放节点会调用：

- `/left/control_enable`、`/right/control_enable`（`std_srvs/srv/SetBool`）；
- `/left/control/joint_states`、`/right/control/joint_states`（`sensor_msgs/msg/JointState`）。

下发前可检查接口是否存在：

```bash
ros2 service type /left/control_enable
ros2 service type /right/control_enable
ros2 topic info /left/control/joint_states -v
ros2 topic info /right/control/joint_states -v
ros2 topic hz /left/feedback/joint_states
ros2 topic hz /right/feedback/joint_states
```

回放只控制左右臂和双夹爪，不下发底盘、升降柱或相机指令。暂停、退出、反馈
超时或异常时会关闭控制门并保持双臂。`--clamp-limits` 仅用于已经检查过的旧数据，
不建议对新录制数据默认启用。

## 6. 路径配置

两个工程各自通过 `configs/paths.yaml` 解析路径。所有本机相对路径以对应工程
根目录为基准，与启动命令所在工作目录无关；环境变量可覆盖配置。真机项目不再
包含 Isaac 路径，也不写死某个 `agilex_ws`。可选驱动 overlay 由部署环境设置：

```bash
export AMMR_AGX_OVERLAY_SETUP='robot_ws/install/setup.bash'
export AMMR_AGX_CAMERA_SETUP='camera_ws/install/setup.bash'
```

## 7. ROS 2 接口

仓库内只保留 `ros2_ws/src/lifting_msg_pkg`。需要编译接口时：

```bash
cd /home/ai/project/yj/ammr_teleop
./scripts/build_ros_interfaces.sh
```

机械臂、底盘、相机和升降柱控制节点均由目标机器人环境提供，不随项目复制。
