# AMMR 数据集可视化与批量校验

`inspect-dataset` 以只读方式扫描一个 LeRobot 数据集，所有 episode 共用
一个 Dashboard，不会为每条数据生成图片或 HTML。它仅支持
`ammr_real_joint14_v1` 数据契约：左臂 6 关节 + 左夹爪 + 右臂 6 关节 +
右夹爪。

## 1. 安装可视化依赖

只有运行 Dashboard 的服务器需要安装：

```bash
cd /home/ai/project/yj/ammr_teleop
/home/ai/miniconda3/envs/tv/bin/python -m pip install -r requirements-analysis.txt
```

AGX Recorder 不需要 Dash/Plotly；不在 AGX 上打开 Dashboard 时可不安装该
可选依赖。

## 2. 启动单页 Dashboard

```bash
cd /home/ai/project/yj/ammr_teleop
./scripts/ammr.sh inspect-dataset \
  --dataset-path /home/ai/project/zw/openpi/dataset/ammr_pick_place
```

默认只监听 `127.0.0.1:8050`，在服务器本机打开：

```text
http://127.0.0.1:8050
```

需要从同一可信局域网的其他电脑访问时：

```bash
./scripts/ammr.sh inspect-dataset \
  --dataset-path /path/to/dataset \
  --host 0.0.0.0 \
  --port 8050
```

然后访问 `http://<server-ip>:8050`。该服务没有身份认证，不应直接暴露到
公网。

## 3. 页面内容

Dashboard 包含：

- episode 总览表：帧数、时长、标称/时间轴/真实采集频率、真实频率来源、
  最大时间间隔、拒绝/重复/目标跳过比例、RMSE、最大 state/action 误差和最大
  action 相邻帧跳变；
- episode × joint 热力图：以每个关节的最大 `|action[t]-action[t-1]|`
  快速定位跳变数据；
- episode 下拉选择：在同一页切换任意 episode；
- 14 个关节的 state/action 叠加曲线；
- 14 个关节的 `action-state` 误差曲线。

机械臂关节单位为 rad，夹爪单位为 m。因为两种单位不同，总览中的
`mean_rmse` 只用于粗略排序，判断问题时应以分关节曲线和热力图为准。

频率定义：

- `Nominal Hz`：`meta/info.json` 中声明的数据集 FPS；
- `Timeline Hz`：由 parquet 标准 `timestamp` 计算，LeRobot 数据可能已将它规范化为
  `frame_index / fps`，因此不能当作真实采集率；
- `Actual capture Hz`：优先读取 `meta/episodes.jsonl` 的
  `quality.metrics.actual_fps`，其次由 `ammr.sync.target_timestamp` 计算。只有两者
  都缺失时才回退到 parquet `timestamp`，并在 `Actual Hz source` 中明确标注。

页面同时显示 `Timeline duration` 和 `Capture duration`。单条 episode 的关节曲线优先
使用 `ammr.sync.target_timestamp` 作为横轴，因此不会把一段真实 102 秒的采集压缩成
LeRobot 标准时间轴上的 63 秒。

`Contract valid` 只表示14维格式、关节名称、数值和限位合法；`Quality valid`
才表示录制频率、拒绝率、重复率等采集质量指标通过。两者不能混为一个
`valid`。

## 4. 只做批量校验

不启动 Web 服务：

```bash
./scripts/ammr.sh inspect-dataset \
  --dataset-path /path/to/dataset \
  --validate-all \
  --no-web
```

如需一份数据集级 JSON 结果（不是每个 episode 一份）：

```bash
./scripts/ammr.sh inspect-dataset \
  --dataset-path /path/to/dataset \
  --validate-all \
  --no-web \
  --summary-json /path/to/dataset_summary.json
```

`--validate-all` 与 `--no-web` 组合时，任意 episode 的 14 维数据契约校验失败都会
返回非零退出码，可用于批处理或 CI。Quality invalid 会在摘要和 JSON 中报告，
但当前不会单独改变进程退出码。原始 parquet 和 `meta/info.json` 始终只读。

## 5. 当前指标边界

`action-state` 是同帧相减，还没有自动补偿机械臂的控制延迟。因此 RMSE
较大不能单独证明数据异常；必须结合 action 跳变和可视化曲线判断。
后续可在不改变当前数据结构的前提下增加延迟估计、速度/加速度/jerk
和多 episode 对比。
